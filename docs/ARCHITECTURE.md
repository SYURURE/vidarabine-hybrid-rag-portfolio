# Architecture

## 1. 目的

本公開版は、ビダラビンを題材にした非公開実習で採用した考え方を、第三者コンテンツを含まない小型デモとして示します。中心となる設計原則は「原文の代わりに根拠IDを運ぶ」「検索根拠が弱いときは生成しない」「キーワードとベクトルの弱点を順位統合で補う」の3点です。

## 2. 入出力

入力コーパスは1行1文書のJSONLです。検索結果は次の2層で返します。

1. `packet`: 質問、検索方式、十分性判定、警告、根拠一覧
2. `response`: 回答、使用根拠ID、警告、生成方式

回答より先に根拠パケットを確定するため、回答生成モデルへ渡した情報を追跡できます。

## 3. キーワード経路

Unicode NFKC正規化、小文字化、英数字単語、日本語文字列と二文字単位を使って一致度を計算します。文書のタイトル、項目、キーワード、本文を検索対象にします。

## 4. ベクトル経路

既定の `portable` バックエンドは、トークンをSHA-256で固定次元へ写像し、L2正規化した疎ベクトルのcosine類似度を使います。これは意味埋め込みではなく、依存関係なしで実行できる再現用の近似経路です。

`ollama` バックエンドを選ぶと、Ollamaの埋め込みAPIを利用できます。モデルやOllamaの版、ハードウェアにより結果が変わる可能性があります。

## 5. 順位統合

キーワード順位とベクトル順位をweighted Reciprocal Rank Fusionで統合します。

```text
score(d) = keyword_weight / (k + keyword_rank(d))
         + vector_weight  / (k + vector_rank(d))
```

既定値は両方の重みが1、`k = 60` です。生スコアの尺度が異なっても、順位を共通の形へ変換できます。

## 6. 根拠十分性ゲート

候補はキーワード生スコアまたはベクトル類似度のどちらかが閾値を超えた場合だけ根拠になります。根拠が0件なら回答モデルを呼ばず、`sufficient_evidence_not_found` を返します。

最新性を尋ねる表現と個別患者相談らしい表現には追加警告を付けます。これは規制対応や医療安全を保証する分類器ではなく、設計意図を示す単純なルールです。

## 7. 回答経路

既定は根拠本文をID付きで返す決定的な抽出デモです。`--use-ollama` を指定した場合だけローカルモデルへ質問と根拠を渡します。回答中の `[source_id]` を確認し、根拠IDがなければ警告します。

## 8. 元実習との差分

元実習では、書籍・CD由来の構造化データ、キーワード索引、Ollama埋め込み、より細かな剤形・相互作用フィルター、段階別評価を使用しました。公開版では第三者データとその派生物を除き、ポータブルな単一ファイル実装と合成データに置き換えています。
